# Pull 控制输入语义统一设计

## 背景

发射机构的 Pull 丝杆当前支持两类控制思路：

- 位置环直接接收归一化行程目标；
- 拉力传感器提供真实拉力，拉力外环再计算行程目标。

校准层已经统一采用 `0.0 = 丝杆最底部`、`1.0 = 丝杆最顶部` 的行程坐标。由于机构的力量与行程方向相反，直接把一个无量纲“小数”传给位置环时，数值越小反而力量越大；而传感器闭环的真实拉力目标则是数值越大力量越大。这种输入趋向不一致，容易在调试和切换控制方式时产生误用。

Push 左右丝杆也采用 `0.0 = 底部`、`1.0 = 顶部` 的行程坐标，但当前没有使用拉力传感器或力量外环。因此，Push 与本次力量语义转换无关，其现有控制保持不变。

## 目标

所有面向操作者的力量指令采用相同趋向：输入数值越大，期望力量越大；输入数值越小，期望力量越小。输入单位不要求相同。

具体目标如下：

- 保留既有行程定义：`0.0 = 底部`、`1.0 = 顶部`。
- 开环力量比例采用 `0.0 = 最小力`、`1.0 = 最大力`。
- 闭环力量采用拉力传感器的真实单位 `g`，目标值越大表示力量越大。
- 开环力量比例通过可配置安全工作区间转换为行程目标。
- 保留直接行程控制入口，供机构调试使用。
- 不改变当前四发已经调好的实际 Pull 目标位置。
- 不新建生产代码模块或测试模块，只修改现有 Booster 头文件和源文件。

## 非目标

- 不修改 Push 左右电机的校准、限位、状态机或目标语义。
- 不改变底层电机类的 `Set_Target_Radian()` 接口。
- 不在本次改动中重新启用当前 PREP_FIRE 中被注释的拉力闭环路径。
- 不标定开环力量比例与真实物理拉力之间的非线性关系；开环比例只表示安全工作区间内的相对力量等级。
- 不增加新的主机单元测试框架或测试文件。

## 输入语义

| 输入 | 单位/范围 | 数值趋向 | 用途 |
| --- | --- | --- | --- |
| Pull 行程比例 | 无量纲 `[0.0, 1.0]` | `0.0` 为底部，`1.0` 为顶部 | 直接行程调试 |
| Pull 开环力量比例 | 无量纲 `[0.0, 1.0]` | 数值越大，期望力量越大 | 正常 PREP_FIRE 位置环路径 |
| Pull 闭环目标拉力 | `g`，非负 | 数值越大，期望力量越大 | 拉力传感器外环 |

这三个输入必须通过名称明确的独立接口设置，不能把力量比例直接传给底层位置目标。

## 架构与接口

### 控制模式

在 `Class_Booster` 中增加 Pull 控制模式：

```cpp
enum Enum_Pull_Control_Mode
{
    Pull_Control_Mode_STROKE_RATIO = 0,
    Pull_Control_Mode_FORCE_RATIO,
    Pull_Control_Mode_TENSION,
};
```

### 公共入口

在 `Class_Booster` 中提供三个语义独立的设置入口：

```cpp
void Set_Pull_Stroke_Ratio(float stroke_ratio);
void Set_Pull_Force_Ratio(float force_ratio);
void Set_Target_Tension_Gram(float tension_g);
bool Configure_Pull_Force_Stroke_Range(float low_force_stroke_ratio,
                                       float high_force_stroke_ratio);
```

每个入口同时保存对应目标并切换到对应控制模式，避免控制模式与目标值不匹配。现有 `Target_Tension`、测量值以及相关 Get/Set 接口统一使用 `float`，力量接口名称明确标注 `Gram`。

周期执行统一经过 Booster 内部 Pull 控制分发函数：

```cpp
void Update_Pull_Control(bool is_first_run);
```

```text
行程比例 ──限幅──────────────→ 目标行程
力量比例 ──限幅、反向映射────→ 目标行程 ──→ Pull 电机位置环
真实拉力 ──传感器拉力外环────→ 目标行程
```

校准、下压扣锁和换弹状态中现有的专用电机动作保持原样；只有需要使用上述目标语义的 PREP_FIRE/调试入口经过统一分发，避免与状态机专用动作冲突。

## 安全工作区间与映射

Pull 开环力量比例默认映射到以下安全工作区间：

```cpp
Low_Force_Stroke_Ratio  = 0.95f;
High_Force_Stroke_Ratio = 0.05f;
```

线性映射公式为：

```cpp
stroke_ratio = Low_Force_Stroke_Ratio
             + force_ratio * (High_Force_Stroke_Ratio
                              - Low_Force_Stroke_Ratio);
```

使用默认配置时等价于：

```cpp
stroke_ratio = 0.95f - 0.90f * force_ratio;
```

关键点如下：

- 力量比例 `0.0` 映射为行程 `0.95`。
- 力量比例 `0.5` 映射为行程 `0.50`。
- 力量比例 `1.0` 映射为行程 `0.05`。
- 力量比例先限幅到 `[0.0, 1.0]`，防止越过配置的安全区间。

`Configure_Pull_Force_Stroke_Range()` 返回配置是否生效。新配置只有同时满足以下条件才生效：

- 两个行程端点均为有限数值且位于 `[0.0, 1.0]`；
- `High_Force_Stroke_Ratio < Low_Force_Stroke_Ratio`。

非法配置被拒绝，并保留上一组有效配置。

## 现有四发参数迁移

当前 PREP_FIRE 位置表为：

```cpp
{0.39f, 0.40f, 0.42f, 0.45f}
```

使用反算公式：

```cpp
force_ratio = (0.95f - stroke_ratio) / 0.90f;
```

迁移为开环力量比例表：

```cpp
{0.622222f, 0.611111f, 0.588889f, 0.555556f}
```

迁移关系如下：

| 原目标行程 | 新力量比例 | 映射后的目标行程 |
| ---: | ---: | ---: |
| 0.39 | 0.622222 | 约 0.39 |
| 0.40 | 0.611111 | 约 0.40 |
| 0.42 | 0.588889 | 约 0.42 |
| 0.45 | 0.555556 | 约 0.45 |

表名同步改为明确表达力量比例的名称。PREP_FIRE 使用 `Set_Pull_Force_Ratio()`，到位判断使用中间层解析后的目标行程，不能再将力量比例直接传给电机位置接口。

## 闭环拉力路径

闭环入口接收真实目标拉力 `tension_g`。目标值越大，拉力外环越趋向增加实际力量，数值方向与开环力量比例一致。

本次改动只统一接口名称、类型和分发边界，不默认启用当前已经注释的 PREP_FIRE 拉力闭环代码。若以后显式选择闭环模式：

- 拉力传感器在线时，继续使用现有 `Pull_Tension_Control()` 计算行程目标；
- 进入闭环拉力模式的首帧，将目标行程初始化为当前归一化位置；
- 拉力传感器离线时，不再更新目标行程，位置环保持最后一次有效目标。若进入模式时传感器已经离线，该目标就是进入时锁存的当前位置；
- 传感器离线不能被视为拉力已经到达目标。

## 错误与边界处理

- 行程比例输入限幅到 `[0.0, 1.0]`。
- 开环力量比例输入限幅到 `[0.0, 1.0]`。
- 负的真实目标拉力按 `0 g` 处理；本次不臆造未经机构标定的最大拉力上限。
- 非有限输入被忽略，不覆盖上一有效目标，也不切换控制模式。
- 非法安全区间不生效，原配置保持不变。
- 模式切换到闭环拉力时，沿用现有首帧初始化逻辑，从当前位置开始调节，避免目标突跳。

6. 使用项目现有 EIDE `unify_builder` 与 ARMClang 配置执行完整固件重编译，确认编译和链接成功。

实机验收时，可依次下发力量比例 `0.0、0.5、1.0`，确认解析目标行程为 `0.95、0.50、0.05`，并通过拉力传感器确认实际力量单调增大。实际力量的单调性最终仍需由机构实测确认。

## 完成标准

- 操作者使用力量比例或真实拉力时，数值越大均表示力量越大。
- 直接行程调试继续采用 `0.0 = 底部`、`1.0 = 顶部`。
- 默认安全区间为低力位置 `0.95`、高力位置 `0.05`，且可安全配置。
- 四发默认位置行为保持不变。
- Push 控制行为保持不变。
- PREP_FIRE 不默认启用拉力闭环。
- ARMClang 完整构建成功。
